# #43 — Fix WorkOutDoors/Strava sync-timing duplicate race (grace period + start-only suppression + self-heal)

**Closed:** 2026-06-06
**Branch:** `claude/elastic-hellman-a0b18c`

## What was wrong

A watch-recorded source (WorkOutDoors, Apple Watch native, Peloton) writes its
`HKWorkout` straight into HealthKit, while the same ride reaches Strava
independently — and the WorkOutDoors→Strava upload frequently *beats* the
watch→phone HealthKit sync. A FitnessLoadTracker sync that runs in that gap
(especially the hourly background fire) finds no HK twin in the ±5min window,
takes the `.noMatch` → create path, and authors its own `HKWorkout`. When the
real workout lands later, the ride exists in HealthKit twice.

Nothing reconciled them afterward: our created copy stores `moving_time` as its
duration while the native twin stores ~`elapsed_time`, and for any ride with
stops that gap exceeds the ±60s tolerance — so both `Matching` and #39's
duplicate detector (same ±60s duration rule) silently failed to pair them. Same
root cause as `completed/37.md`.

## The key insight that shapes the whole design

**The two copies share no common identifier.** `stravaActivityId` is not an
intrinsic HealthKit property — it's a custom metadata key *our app* invents and
stamps onto workouts *we* author. WorkOutDoors writes its workout independently
and stamps nothing of the sort. So only our copy carries a Strava id; the native
twin carries none. You cannot pair them by id — only by the one thing they share:
the same real-world ride, hence ~same start time. Every gate below keys on
**start-time proximity + source (ours vs foreign)**, never a shared id. (This was
a live point of confusion during the session — worth stating plainly.)

## The fix — three coupled workstreams on the `.noMatch` branch

- **A — grace period before create.** A ride that ended < `createGracePeriod` ago
  with no HK twin is **deferred** (`.deferredAwaitingHKTwin`), not created; the
  24h overlap window re-fetches it once the source app writes its workout to HK.
  `createGracePeriod = 3h` (Tom's pick; hidden constant, revisit after live data).
- **B — start-time-only create suppression.** Before creating, look for foreign
  (non-app-authored, non-proxy) workouts of the target type starting within ±60s,
  *regardless of duration* — catches the twin that is present but duration-rejected.
  Exactly one → attach effort/distance to it; >1 → `multipleMatches`; 0 → fall
  through to A.
- **C — self-heal an existing dup.** When a native twin and our app-authored copy
  of the same ride coexist, ensure effort on the twin, then delete **our** copy +
  its samples (HR/energy/distance + related effort). Fenced by a hard contract:
  the deletion candidate is app-authored **and** carries the exact `stravaActivityId`,
  is not a proxy, and a qualifying foreign twin exists (no twin ⇒ no delete, which
  protects a legitimately Strava-only ride we created earlier). Native twin always
  wins. New `.healedDuplicate(effort:)` status (`isWrite = true` — a heal ensures
  effort on the right workout, so it counts toward the #41 "synced" headline).

`.noMatch` ordering reworked so a native twin always wins over our copy: strict
match → B → own-id dedup (only when no twin) → A defer → create. Detection stays
source-agnostic, so Apple Watch native / Peloton races are covered identically.

## Two bugs found mid-flight (both surfaced by Tom)

1. **C was only wired into the `.noMatch`/B path, not the strict `.matched` path.**
   The design called for the heal on *both*. The common WorkOutDoors dup whose
   twin's duration happens to land within ±60s of Strava elapsed_time takes the
   strict `.matched` branch, where the heal wasn't running — so a pre-existing dup
   could have gone unhealed. Fix (`b85c7a4`): hoist the reconcile candidates +
   mapped type above the Matching switch, run a shared `healOwnCopyIfPresent` on
   `.matched` too, guarded by `!isAppAuthored(matched)` so it only deletes when the
   match landed on the foreign twin — never when the match *is* our own legit copy
   (the Strava-only / pre-twin case, which has no twin and must survive).

   In the end Tom's actual dup (durations 66:52 vs 67:32, ~5 min under Strava
   elapsed) took the `.noMatch` → B → C path; but the `.matched`-path heal is the
   needed coverage for the variant where the twin's duration ≈ elapsed_time.

2. **The "Possible duplicates" (#39) panel showed a ghost after a heal.**
   `collectDuplicates` captures the cluster at the *start* of processing a ride —
   while our copy still exists — and only then does the heal delete our copy. So a
   healed ride briefly showed "Removed dup + Effort N" *and* a "Possible duplicates"
   entry listing the copy just deleted. Fix (`3f7c315`): after the delete, drop the
   deleted workout from any cluster in `duplicateClusters`; a cluster left with
   fewer than two members is no longer a duplicate.

Plus one cosmetic: `deleteObjects(of:predicate:)` returns a discardable `Bool`,
and wrapping the best-effort effort-delete in `try?` made it `Bool?` → unused-result
warning; discarded with `_ =` (`5ec9efd`).

## How the heal deletes cleanly

`HealthKitManager.deleteWorkoutWithSamples` guards `isAppAuthored` (compares
`sourceRevision.source.bundleIdentifier` to `HKSource.default()`), then deletes
the workout's collected samples (HR/energy/distance, via
`predicateForObjects(from: workout)`) and any related effort
(`predicateForWorkoutEffortSamplesRelated`) before the workout itself — deleting
only the shell would orphan samples that keep double-counting in the rollups
(#37). All deleted types are in `shareTypes`, so we hold delete authorization.
For an outdoor ride our copy carries its own native distance sample (no proxy),
so nothing is orphaned.

## Decisions / scope notes

- **`createGracePeriod` = 3h**, hidden constant. Tom's call over the design's
  tentative 6h; tighter so a genuinely Strava-only ride waits less for its effort.
- **`.healedDuplicate` counts as a write** (`isWrite = true`).
- **Native twin always wins; heal deletes our copy, never the foreign one.**
- **Source-agnostic** — no hardcoded "WorkOutDoors"/device names.

### Deliberately not handled (deferred)

- **The no-stop-ride edge.** If our copy *and* the twin have near-identical
  durations (a ride with no stops, so `moving_time ≈ elapsed_time`), the strict
  matcher sees two valid matches and returns `multipleMatches` → no heal, shown as
  "Multiple matches". The heal reliably fires for rides *with* stops (the
  motivating WorkOutDoors-outdoor case, where our copy is duration-rejected and
  only the twin strict-matches, or both are rejected → `.noMatch` → B). Extending
  the heal to the `multipleMatches` case wasn't in the design fixtures; left for a
  follow-up if it shows up in the wild.
- **A wide historical scan** to heal dups outside the recent sync window — A/B/C
  only touch rides in the windows actually synced (like #39's deferred wide-scan).
- **Broadening the global matcher** to reconcile `moving_time`/`elapsed_time`
  generally — a separate design question (also out of scope in `completed/37.md`).
