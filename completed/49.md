# #49 — Remove #37 distance-proxy enrichment (double-counted native distance)

**Closed:** 2026-06-25
**Branch:** `claude/peloton-distance-sync-xdtq2g`

## What was wrong

#37 authored a 1-second "proxy" cycling workout carrying the Strava-equivalent
distance whenever a matched cycling ride lacked native distance. The gate
(`DistanceEnrichment.shouldWrite` → `workoutHasNativeCyclingDistance`) only
checked for native distance **at sync time**. But Peloton routinely lands its
indoor ride in HealthKit *without* distance and then backfills native
`distanceCycling` onto its own workout later — specifically the next time the
Peloton app is opened in the foreground (observable: the past-workout icon
flips white→black as it updates).

So the common sequence double-counts:

1. FitnessLoadTracker syncs first → no native distance yet → writes a proxy.
2. Peloton app opened later → backfills native distance onto its own workout.
3. Both the proxy and the native sample now exist for the same ride → the
   cycling-distance rollup reads high.

`hasDistanceProxyWorkout` only prevented a *second proxy*; nothing retracted the
proxy once native distance appeared. Tom hit this in practice — opening Peloton
to "fix" a distance-less ride was exactly what produced the duplicate.

## Why removal, not a fix

Two alternatives were weighed and rejected:

- **"Open the Peloton app on detection, write effort only."** Tom's original
  idea. Infeasible: you can't launch another app from a background sync (the
  primary, automatic path), there's no deterministic Peloton "sync now"
  callback to await, and it would force hardcoded Peloton-source detection that
  #37 deliberately designed out. It also yanks the user into Peloton each time.
- **Self-healing reconcile** (delete the proxy when native distance later
  appears). Viable, but more moving parts to maintain for a feature whose
  entire value is replicating data Peloton already provides on its own.

Conclusion: native Peloton distance is the better data and arrives unaided. The
proxy is a net negative. Remove it.

## What was removed vs kept

**Removed — the proxy *write* path and its scaffolding:**

- `DistanceEnrichment.swift` + `DistanceEnrichmentTests.swift` (whole files).
- `SyncOrchestrator`: `enrichDistanceIfNeeded`, `matchedStatus`, the
  `writtenWithDistance` / `addedDistance` statuses (+ their `isWrite` /
  `summaryLabel` branches), and the `wroteDistance` plumbing.
  `handleMatchedWorkout` now writes effort only and lost its unused `activity`
  parameter; its status collapses to `.written` / `.skippedAlreadyHasEffort`.
- `HealthKitManager`: `writeDistanceProxyWorkout`, `hasDistanceProxyWorkout`,
  `workoutHasNativeCyclingDistance`, `distanceProxyDuration`.
- `StravaActivity.distance` (proxy-only; threaded out of `asSummary` too).
- `ContentView`: the two distance status labels.

**Kept — recognition guards (leftover proxies persist on-device):**

- `HealthKitManager.isDistanceProxy` + `distanceProxyMetadataKey` (the guard
  reads the key, so the key stays).
- The matcher's candidate filter `workouts(in:).filter { !isDistanceProxy($0) }`
  and the `CreatePathReconciliation.ReconcileCandidate.isDistanceProxy` checks.

Existing proxies were **not** swept by code — Tom deletes the 1-second / X-mile
cycling entries manually in the Health app (decided over building a one-time
cleanup tool like #37's retired sweeper). Until he does, those proxies live in
HealthKit, so the matcher and the #43 heal must still recognize and exclude
them — that's why the recognition guards stay rather than being deleted with the
rest. They become dead no-ops only once every legacy proxy is gone, with no
reliable signal for that, so they're left in place at low cost.

**Kept — shared helpers (removing them would break #39 / #43 / the create path):**

- `stravaActivityId` metadata + `customMetadataPrefix` — create-path dedup and
  all app-authored workout metadata.
- `distanceMeters` + the `distanceCycling` **read** permission — now feed only
  #39's duplicate-detection display; the readTypes comment was re-pointed at #39
  (its sole remaining consumer) since the #37 native-distance guard is gone.
- `StravaActivityDetail.distance` — used by the full-workout create-path blueprint.
